开篇先写「为什么读这篇」：读者现在卡在哪，看完能做什么。两三句话就够，别写客套话。

## 一格可以放很多篇

`track` + `stage` 定位到目录里的一格，**一格里的篇数不限**。编号（1.1、1.2）是自动算的：

- 默认按 `pubDate` 从早到晚排，也就是「先写的先读」，新加的一篇接在末尾；
- 想把新写的一篇插到前面，给它一个比同格其它篇更小的 `order`。

所以不需要一次写完整层：想清楚一小块就可以发一篇，剩下的留给下一个人。

## 第一个小节

正文用 Markdown 写就行。注意几点：

- 命令、路径、变量用 `行内代码`
- 代码块务必标语言，行内注释用中文
- 表格适合写「对比」和「排查顺序」，不适合写长段落

```bash
# 示例：命令后面跟一句注释，说明这条在干什么
npm run dev
```

### 画图用 mermaid

需要流程图、时序图、状态图时，直接写 `mermaid` 代码块，构建时不会被当成代码染色，
浏览器里渲染成图，颜色自动跟站点的设计令牌走：

````markdown
```mermaid 图下面这行小字是图注，可省。
flowchart LR
  A["先这样"] -- "然后" --> B["再那样"]
```
````

标签里可以放 `<br/>` 换行。渲染失败时源码会留在原地并标出来，不会变成空白。

> 引用块用来放「容易忽略的提醒」或「经验法则」，一篇里别超过两处。

## 结尾给一条下一步

最后一段回答「然后呢」：下一篇读什么、去哪提问题。链接到站内其它笔记时用绝对路径，
例如 `/blog/git-github-workflow/`。

想补上方向索引里灰着的题目，就把 `track` 和 `stage` 填成那一格，
索引页会自动把它从「想写」变成链接。
